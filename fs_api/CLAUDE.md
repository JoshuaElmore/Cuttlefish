# fs_api

Go REST API for the Cuttlefish filesystem index. Single binary, `package main`, no frameworks — just the standard library plus a few focused packages.

## Architecture

### File layout

| File | Responsibility |
|---|---|
| `main.go` | Server entry point: loads config, registers routes, starts HTTP server, serves compiled UI |
| `config.go` | Loads `fs_config.yml`, validates required fields, builds the PostgreSQL connection string |
| `auth.go` | Session issuance/validation (JWT in cookie), auth middleware, local login handler, OIDC flow |
| `queries.go` | **The query layer.** Every SQL statement except search lives here, plus `apiError` and the paging clamps |
| `handlers.go` | All `/api/*` route handlers — thin adapters from HTTP to `queries.go` |
| `search.go` | `/api/search`: rule→SQL translation and `executeSearch` |
| `mcp.go` | MCP server: tools, the index-status resource, bearer auth, transport mounting |
| `middleware.go` | `loggingMiddleware`, `respondJSON`, `respondError` helpers, and `debugLog` |
| `models.go` | Shared data types: `FileInfo`, `UserStats`, `DirAggregates`, `SearchRule` |
| `docs/` | Swagger doc files generated by `swag init` |

### Two front ends, one query layer

There are two ways into the same data — the REST API for the browser UI, and the
MCP server for AI clients — and neither writes SQL of its own. Both call
`queries.go` / `executeSearch`, so a change to what a listing contains or to how
an unresolved uid renders lands on both at once. `TestMCPMatchesREST` compares
the two byte for byte on the same entry and fails if anyone reimplements one.

The layer reports failures with `apiError{Status, Message}`. That type carries
the "not found" / "you asked wrong" / "we broke" distinction out of the place
that can tell them apart: `respondQueryError` turns it into an HTTP status,
`mcpToolError` into a tool error. Anything *not* an `apiError` is an internal
fault — logged server-side, reported to the caller as a bare failure, never
quoted, since those messages name tables, columns and hosts.

### Database schema (read-only from the API)

The API queries a PostgreSQL database populated by `fs_indexer` and `fs_aggregator`:

- **`filesystem_index`** — one row per filesystem entry; columns include `path`, `path_hash`, `parent_hash`, `size_bytes`, `file_type` (1=file, 2=dir, 3=symlink, 0=other), `permissions`, `uid`, `gid`, `mtime`, `atime`, `ctime`. Directory children are found via `parent_hash`.

  The two single-entry endpoints split on **directory vs. not**, not file vs. not: `GetDirStats` rejects `file_type != 2` and `GetFileStats` rejects only `file_type == 2`, so symlinks, sockets, FIFOs and device nodes resolve through the file endpoint. `/api/list` type-checks nothing, so any stricter rule here produces an entry that appears in a listing but 400s when the UI asks for its detail — which is exactly what symlinks did.

  `path_raw` holds the exact filename bytes and is `NULL` unless they differ from `path` (Unix names are arbitrary bytes, so `path` is a lossy UTF-8 rendering for the rare name that isn't valid UTF-8). It is surfaced on `FileInfo` as base64 `path_raw`, omitted when absent. **Its presence means `path` cannot be round-tripped** — two entries in one listing may show an identical `path` and differ only here. To address such an entry, percent-encode the decoded `path_raw` bytes into `?path=`; `pathHash` hashes whatever bytes arrive, and Go strings are byte sequences, so this works without special handling.

  `path_hash` and `parent_hash` are SHA-256 of the **raw path bytes** truncated to `pathHashLen` (16) bytes, recomputed here by `pathHash` in `handlers.go` so path lookups hit the primary key instead of scanning the unindexed `path` column. **This width must stay equal to `fs_common::PATH_HASH_LEN` in the Rust binaries that write the rows** — if the two drift, every lookup misses while both sides still look correct in isolation, and the API answers 404 for a fully indexed filesystem. `checkPathHashWidth` (called from `main`) logs a non-fatal startup warning when the stored width doesn't match this build.
- **`identity_map`** — maps `(id, id_type)` → `name`; `id_type` is `'uid'` or `'gid'`.
- **`user_stats`** / **`dir_stats`** — pre-aggregated totals written by `fs_aggregator`; queried by `/api/user/list`, `/api/group/list`, and the `include_stats` path on directory endpoints.
- **`scan_sessions`** — one row per `fs_indexer` or `fs_aggregator` run (`session_id`, `scan_type`, `status`, `files_scanned`, `started_at`, `ended_at`); queried by `/api/scans`. `status` is `'running'`, `'success'`, or `'failed'`, written by the Rust process itself (via `fs_common`'s scan-session helpers) — `fs_api` only reads it. `files_scanned` is likewise written directly by the scanning process rather than derived, so this table is not fully normalized against `filesystem_index` by design.

All queries use parameterized statements (`$1`, `$2`, …) except `listIdentityStats`, which uses `fmt.Sprintf` for `ORDER BY` with an allowlist-validated column and direction.

`SearchFiles` translates a PostgreSQL regex parse failure (SQLSTATE `2201B`, or `54000` for an over-complex pattern) into **400** rather than 500, but only when the request actually used a `regex`/`regex_i` operator, so unrelated query failures still read as server errors. The validation is deliberately left to PostgreSQL: those operators compile as POSIX ARE, which differs from Go's RE2, so pre-checking with `regexp.Compile` would reject valid patterns and accept invalid ones.

### Authentication

Two modes, selected by whether `auth.oidc.issuer` is set in config:

**Local mode** — single username/password stored in config. Compared with `crypto/subtle.ConstantTimeCompare` to prevent timing attacks.

**OIDC mode** — standard OAuth2 Authorization Code flow:
1. `GET /auth/oidc/start` → generates a random state, sets `oidc_state` cookie, redirects to provider
2. Provider redirects to `GET /auth/callback` → validates state, exchanges code, verifies ID token, extracts email/sub as username
3. Session issued

**Session** — HS256-signed JWT stored in an `HttpOnly`, `SameSite=Lax` cookie (`session`). The `sessionUser()` function validates the token on every request; `authMiddleware` wraps all `/api/*` routes.

### Route map

```
GET  /auth/mode           — returns "local" or "oidc" (unauthenticated)
GET  /auth/me             — returns current user if session is valid
POST /auth/login          — local login (JSON body: username, password)
POST /auth/logout         — clears session cookie
GET  /auth/oidc/start     — begins OIDC flow (oidc mode only)
GET  /auth/callback       — OIDC callback (oidc mode only)

GET  /api/list            — list directory children (?path=, &include_stats=true)
GET  /api/file/stats      — single non-directory entry's metadata (?path=)
GET  /api/dir/stats       — single directory metadata (?path=, &include_stats=true)
GET  /api/user/list       — user storage stats (?sort_by=, &order=, &limit=, &offset=)
GET  /api/group/list      — group storage stats (same params)
GET  /api/scans           — scan_sessions history, newest first (?limit=, &offset=); scan_type, status and files_scanned are read straight off the row

POST /mcp                 — MCP endpoint (Streamable HTTP); path and port are configurable

GET  /swagger/            — Swagger UI (unauthenticated)
/                         — serves compiled UI from ui/build/; falls back to index.html for SPA routing
```

## MCP server

`fs_api` also speaks the [Model Context Protocol](https://modelcontextprotocol.io),
so an AI client can query the index directly instead of driving the REST API.
Built on `github.com/modelcontextprotocol/go-sdk`, transport is Streamable HTTP,
and the endpoint is mounted on the main listener at `/mcp` by default.

**It is read-only by construction.** Nothing in `mcp.go` writes, every tool is
annotated `ReadOnlyHint`, and only metadata is indexed — file *contents* are
never in the database, so they cannot be read through this server.

### Tools

| Tool | REST counterpart | Notes |
|---|---|---|
| `get_entry_stats` | `/api/file/stats` + `/api/dir/stats` | One tool, not two: a model doesn't know an entry's type before it looks. Returns any entry; attaches directory rollups when there are any |
| `list_directory` | `/api/list` | Direct children, one level |
| `search_files` | `POST /api/search` | Same rule grammar, same allowlists |
| `list_user_stats` | `/api/user/list` | |
| `list_group_stats` | `/api/group/list` | |
| `list_scan_sessions` | `/api/scans` | How fresh the snapshot is |

Resource `cuttlefish://index/status` gives the newest indexer and aggregator
run plus a row-count estimate — `pg_class.reltuples`, not `COUNT(*)`, which on a
10⁸-row index is not a trade worth making to answer "is this populated". It is
omitted entirely when the table has never been analyzed (`reltuples` = -1).

The server's `Instructions` string is where a model learns the vocabulary: the
`file_type` codes, that timestamps are epoch seconds, and above all that this is
a *snapshot* and not the live filesystem — so a missing path means "not in the
last scan", not "not on disk".

### Paging

Every tool pages, defaulting to 100 rows and capping at 1000 — far below the
REST defaults, because these results land in a context window where a
10 000-entry listing isn't a big response, it's a useless one. Each tool fetches
`limit + 1` rows and reports `truncated` from whether the extra row appeared, so
the flag is exact rather than inferred from a full page.

`queryChildren` takes a limit of 0 from the REST handler (every child, index-scan
order, unchanged behavior) and a positive one from MCP, which additionally sorts
by path — paging without a stable order silently skips and repeats entries. That
sort is the cost: `WHERE parent_hash = $1 ORDER BY path LIMIT n` has no composite
index behind it, so a page of a very wide directory sorts the whole child set
(~7 ms per 100-entry page out of 20 000 children on the benchmark box, and ~15 ms
at offset 15 000). Acceptable for agent traffic; worth an index on
`(parent_hash, path)` if it ever becomes a hot path.

### Authentication

The endpoint sits inside the existing session boundary — `mcpAuthorized` accepts,
in order:

1. the `session` cookie, for a browser-hosted client on this origin;
2. the same signed session token in `Authorization: Bearer <token>` — an MCP
   client has no cookie jar, so a headless one logs in once and reuses the token;
3. the optional static `mcp.token` from config, for a client that cannot log in
   at all. Compared in constant time, and only when non-empty, so an unset token
   can't turn an empty `Authorization` header into a valid credential.

A rejection is a 401 carrying `WWW-Authenticate: Bearer`, which is what tells a
spec-compliant client the endpoint wants a credential rather than that it's
broken.

`DisableLocalhostProtection: true` is deliberate, and `TestMCPBehindReverseProxy`
holds it in place. The SDK's DNS-rebinding guard rejects any request whose
*local* socket address is loopback while the `Host` header isn't — precisely
what a same-host TLS-terminating proxy sends, and it fires whether the server is
bound to `127.0.0.1` or `0.0.0.0`, since the proxy's connection is loopback
either way. Leaving it on would 403 the deployment `fs_config_template.yml`
recommends. The guard also buys little here: it exists for local servers that
trust anything reaching them, and every request here needs a credential a
rebound page cannot obtain — cookies are bound to the real origin, and the
bearer token never lives in a browser.

Obtaining a token for a headless client:

```bash
curl -s -c - -X POST http://host:8080/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"..."}' | awk '/session/{print $7}'
```

That token expires in 24 hours (`issueSession`); `mcp.token` does not, which is
the reason it is opt-in and length-checked.

### Config

```yaml
mcp:
  enabled: true           # default; false disables the endpoint entirely
  path: "/mcp"            # must be absolute, may not shadow /, /api, /auth, /swagger
  listen_addr: ""         # non-empty moves MCP to its own listener, and off the main one
  token: ""               # optional static bearer credential, >= 32 chars
```

Absent `mcp` section means enabled at `/mcp`: the endpoint adds no trust the
REST API doesn't already grant, so opt-in would only mean every deployment
pastes the same line. `Enabled` is a `*bool` precisely so "absent" and "false"
stay distinguishable.

`listen_addr` is exclusive, never additive — a deployment that separates the
agent-facing port from the UI port does it to firewall them differently, and a
second copy on the main port would undo that. A failure on the dedicated
listener is fatal: a live server silently missing its configured MCP port is not
observable from outside.

### Tests

`mcp_test.go` needs no database — it covers the tool list, the generated
schemas, input validation, the paging helpers, auth and config validation.
`mcp_integration_test.go` skips itself unless `CUTTLEFISH_TEST_DSN` is set:

```bash
make test-api   # or:
cd fs_api && CUTTLEFISH_TEST_DSN="host=localhost user=postgres password=postgres dbname=fs_index sslmode=disable" go test ./...
make bench-api  # tool-call benchmarks, same DSN
```

It builds a throwaway schema, seeds a small tree, drives every tool (in-memory
*and* over real HTTP through the auth middleware), and drops the schema. Before
any DDL it asserts `current_schema()` is the scratch schema, so a `search_path`
that didn't take fails the run instead of creating tables in `public`.

### Config (`fs_config.yml`)

```yaml
database:
  host: localhost
  user: postgres
  password: "..."
  dbname: fs_index
  sslmode: require   # never use "disable" in production

auth:
  session_secret: "..."  # must be ≥32 chars and not the example default

  local:                 # used when auth.oidc.issuer is absent
    username: "..."
    password: "..."

  oidc:                  # when set, local auth is ignored
    issuer: "https://accounts.google.com"
    client_id: "..."
    client_secret: "..."
    redirect_url: "http://host/auth/callback"

mcp:                     # see "MCP server" above; the whole section is optional
  enabled: true
  path: "/mcp"
```

`config.go` fatally rejects an empty, default-example, or short-than-32-char `session_secret` at startup, and likewise an `mcp.path` that isn't absolute or that shadows an existing route, or an `mcp.token` shorter than 32 characters.

## Build

Use the root Makefile from the repo root:

```bash
make build-api        # build the Go binary (fs_api/fs_api)
make swagger-api      # regenerate Swagger docs then build
make run-api          # swagger + build-ui + build-api + run
make test-api         # go test (DB-backed MCP tests need CUTTLEFISH_TEST_DSN)
make all              # build everything (indexer, aggregator, ui, api)
```

For a debug build (enables `debugLog` per-request logging):

```bash
make build-api-debug
# or directly:
cd fs_api && go build -ldflags "-X main.debugMode=1" -o fs_api .
```

`debugMode` is a linker-set string in `middleware.go`, empty in a normal build. It is deliberately **not** a `//go:build debug` file pair: mutually exclusive tagged files always leave one of the two outside the active build configuration, and gopls reports "No packages found" on whichever one the editor isn't type-checking.
