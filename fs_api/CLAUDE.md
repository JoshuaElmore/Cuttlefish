# fs_api

Go REST API for the Cuttlefish filesystem index. Single binary, `package main`, no frameworks — just the standard library plus a few focused packages.

## Architecture

### File layout

| File | Responsibility |
|---|---|
| `main.go` | Server entry point: loads config, registers routes, starts HTTP server, serves compiled UI |
| `config.go` | Loads `fs_config.yml`, validates required fields, builds the PostgreSQL connection string |
| `auth.go` | Session issuance/validation (JWT in cookie), auth middleware, local login handler, OIDC flow |
| `handlers.go` | All `/api/*` route handlers — directory listing, file stats, user/group stats |
| `middleware.go` | `loggingMiddleware`, `respondJSON`, `respondError` helpers, and `debugLog` |
| `models.go` | Shared data types: `FileInfo`, `UserStats`, `DirAggregates` |
| `docs/` | Swagger doc files generated by `swag init` |

### Database schema (read-only from the API)

The API queries a PostgreSQL database populated by `fs_indexer` and `fs_aggregator`:

- **`filesystem_index`** — one row per filesystem entry; columns include `path`, `path_hash`, `parent_hash`, `size_bytes`, `file_type` (1=file, 2=dir), `permissions`, `uid`, `gid`, `mtime`, `atime`, `ctime`. Directory children are found via `parent_hash`.

  `path_raw` holds the exact filename bytes and is `NULL` unless they differ from `path` (Unix names are arbitrary bytes, so `path` is a lossy UTF-8 rendering for the rare name that isn't valid UTF-8). It is surfaced on `FileInfo` as base64 `path_raw`, omitted when absent. **Its presence means `path` cannot be round-tripped** — two entries in one listing may show an identical `path` and differ only here. To address such an entry, percent-encode the decoded `path_raw` bytes into `?path=`; `pathHash` hashes whatever bytes arrive, and Go strings are byte sequences, so this works without special handling.

  `path_hash` and `parent_hash` are SHA-256 of the **raw path bytes** truncated to `pathHashLen` (16) bytes, recomputed here by `pathHash` in `handlers.go` so path lookups hit the primary key instead of scanning the unindexed `path` column. **This width must stay equal to `fs_common::PATH_HASH_LEN` in the Rust binaries that write the rows** — if the two drift, every lookup misses while both sides still look correct in isolation, and the API answers 404 for a fully indexed filesystem. `checkPathHashWidth` (called from `main`) logs a non-fatal startup warning when the stored width doesn't match this build.
- **`identity_map`** — maps `(id, id_type)` → `name`; `id_type` is `'uid'` or `'gid'`.
- **`user_stats`** / **`dir_stats`** — pre-aggregated totals written by `fs_aggregator`; queried by `/api/user/list`, `/api/group/list`, and the `include_stats` path on directory endpoints.
- **`scan_sessions`** — one row per `fs_indexer` or `fs_aggregator` run (`session_id`, `scan_type`, `status`, `files_scanned`, `started_at`, `ended_at`); queried by `/api/scans`. `status` is `'running'`, `'success'`, or `'failed'`, written by the Rust process itself (via `fs_common`'s scan-session helpers) — `fs_api` only reads it. `files_scanned` is likewise written directly by the scanning process rather than derived, so this table is not fully normalized against `filesystem_index` by design.

All queries use parameterized statements (`$1`, `$2`, …) except `listIdentityStats`, which uses `fmt.Sprintf` for `ORDER BY` with an allowlist-validated column and direction.

`SearchFiles` translates a PostgreSQL regex parse failure (SQLSTATE `2201B`, or `54000` for an over-complex pattern) into **400** rather than 500, but only when the request actually used a `regex`/`regex_i` operator, so unrelated query failures still read as server errors. The validation is deliberately left to PostgreSQL: those operators compile as POSIX ARE, which differs from Go's RE2, so pre-checking with `regexp.Compile` would reject valid patterns and accept invalid ones.

### Authentication

Two modes, selected by whether `auth.oidc.issuer` is set in config:

**Local mode** — single username/password stored in config. Compared with `crypto/subtle.ConstantTimeCompare` to prevent timing attacks.

**OIDC mode** — standard OAuth2 Authorization Code flow:
1. `GET /auth/oidc/start` → generates a random state, sets `oidc_state` cookie, redirects to provider
2. Provider redirects to `GET /auth/callback` → validates state, exchanges code, verifies ID token, extracts email/sub as username
3. Session issued

**Session** — HS256-signed JWT stored in an `HttpOnly`, `SameSite=Lax` cookie (`session`). The `sessionUser()` function validates the token on every request; `authMiddleware` wraps all `/api/*` routes.

### Route map

```
GET  /auth/mode           — returns "local" or "oidc" (unauthenticated)
GET  /auth/me             — returns current user if session is valid
POST /auth/login          — local login (JSON body: username, password)
POST /auth/logout         — clears session cookie
GET  /auth/oidc/start     — begins OIDC flow (oidc mode only)
GET  /auth/callback       — OIDC callback (oidc mode only)

GET  /api/list            — list directory children (?path=, &include_stats=true)
GET  /api/file/stats      — single file metadata (?path=)
GET  /api/dir/stats       — single directory metadata (?path=, &include_stats=true)
GET  /api/user/list       — user storage stats (?sort_by=, &order=, &limit=, &offset=)
GET  /api/group/list      — group storage stats (same params)
GET  /api/scans           — scan_sessions history, newest first (?limit=, &offset=); scan_type, status and files_scanned are read straight off the row

GET  /swagger/            — Swagger UI (unauthenticated)
/                         — serves compiled UI from ui/build/; falls back to index.html for SPA routing
```

### Config (`fs_config.yml`)

```yaml
database:
  host: localhost
  user: postgres
  password: "..."
  dbname: fs_index
  sslmode: require   # never use "disable" in production

auth:
  session_secret: "..."  # must be ≥32 chars and not the example default

  local:                 # used when auth.oidc.issuer is absent
    username: "..."
    password: "..."

  oidc:                  # when set, local auth is ignored
    issuer: "https://accounts.google.com"
    client_id: "..."
    client_secret: "..."
    redirect_url: "http://host/auth/callback"
```

`config.go` fatally rejects an empty, default-example, or short-than-32-char `session_secret` at startup.

## Build

Use the root Makefile from the repo root:

```bash
make build-api        # build the Go binary (fs_api/fs_api)
make swagger-api      # regenerate Swagger docs then build
make run-api          # swagger + build-ui + build-api + run
make all              # build everything (indexer, aggregator, ui, api)
```

For a debug build (enables `debugLog` per-request logging):

```bash
make build-api-debug
# or directly:
cd fs_api && go build -ldflags "-X main.debugMode=1" -o fs_api .
```

`debugMode` is a linker-set string in `middleware.go`, empty in a normal build. It is deliberately **not** a `//go:build debug` file pair: mutually exclusive tagged files always leave one of the two outside the active build configuration, and gopls reports "No packages found" on whichever one the editor isn't type-checking.

## Key dependencies

- `github.com/golang-jwt/jwt/v5` — JWT signing and verification
- `github.com/coreos/go-oidc/v3` + `golang.org/x/oauth2` — OIDC/OAuth2 client
- `github.com/lib/pq` — PostgreSQL driver
- `github.com/swaggo/http-swagger` — Swagger UI handler
- `gopkg.in/yaml.v3` — config parsing
