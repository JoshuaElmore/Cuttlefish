# fs_api

Go REST API for the Cuttlefish filesystem index. Single binary, `package main`, no frameworks — just the standard library plus a few focused packages.

## Architecture

### File layout

| File | Responsibility |
|---|---|
| `main.go` | Server entry point: loads config, registers routes, starts HTTP server, serves compiled UI |
| `config.go` | Loads `fs_config.yml`, validates required fields, builds the PostgreSQL connection string |
| `auth.go` | Server-side sessions (`sessions` table, OIDC re-check), roles and path access (`access`, `resolveAccess`, `allows`), auth/admin/full-access middleware, local login, OIDC flow, `ensureAuthTables` |
| `admin.go` | `/api/admin/grants` handler (admin only) |
| `handlers.go` | All `/api/*` route handlers — directory listing, file stats, user/group stats |
| `middleware.go` | `loggingMiddleware`, `respondJSON`, `respondError` helpers, and `debugLog` |
| `models.go` | Shared data types: `FileInfo`, `UserStats`, `DirAggregates` |
| `docs/` | Swagger doc files generated by `swag init` |

### Database schema

The API reads the tables populated by `fs_indexer` and `fs_aggregator`, and owns two of its own (below). It is **not** read-only on the DB: its user needs CREATE on first start and SELECT/INSERT/UPDATE/DELETE on `sessions` and `access_grants`.

- **`filesystem_index`** — one row per filesystem entry; columns include `path`, `path_hash`, `parent_hash`, `size_bytes`, `file_type` (1=file, 2=dir, 3=symlink, 0=other), `permissions`, `uid`, `gid`, `mtime`, `atime`, `ctime`. Directory children are found via `parent_hash`.

  The two single-entry endpoints split on **directory vs. not**, not file vs. not: `GetDirStats` rejects `file_type != 2` and `GetFileStats` rejects only `file_type == 2`, so symlinks, sockets, FIFOs and device nodes resolve through the file endpoint. `/api/list` type-checks nothing, so any stricter rule here produces an entry that appears in a listing but 400s when the UI asks for its detail — which is exactly what symlinks did.

  `path_raw` holds the exact filename bytes and is `NULL` unless they differ from `path` (Unix names are arbitrary bytes, so `path` is a lossy UTF-8 rendering for the rare name that isn't valid UTF-8). It is surfaced on `FileInfo` as base64 `path_raw`, omitted when absent. **Its presence means `path` cannot be round-tripped** — two entries in one listing may show an identical `path` and differ only here. To address such an entry, percent-encode the decoded `path_raw` bytes into `?path=`; `pathHash` hashes whatever bytes arrive, and Go strings are byte sequences, so this works without special handling.

  `path_hash` and `parent_hash` are SHA-256 of the **raw path bytes** truncated to `pathHashLen` (16) bytes, recomputed here by `pathHash` in `handlers.go` so path lookups hit the primary key instead of scanning the unindexed `path` column. **This width must stay equal to `fs_common::PATH_HASH_LEN` in the Rust binaries that write the rows** — if the two drift, every lookup misses while both sides still look correct in isolation, and the API answers 404 for a fully indexed filesystem. `checkPathHashWidth` (called from `main`) logs a non-fatal startup warning when the stored width doesn't match this build.
- **`identity_map`** — maps `(id, id_type)` → `name`; `id_type` is `'uid'` or `'gid'`.
- **`user_stats`** / **`dir_stats`** — pre-aggregated totals written by `fs_aggregator`; queried by `/api/user/list`, `/api/group/list`, and the `include_stats` path on directory endpoints.
- **`sessions`** — one row per live login: `id_hash` (SHA-256 of the cookie value, PK), `username`, `groups TEXT[]`, `refresh_token`, `created_at`, `checked_at`, `expires_at`.
- **`access_grants`** — `id`, `group_name`, `path_prefix`, `created_by`, `created_at`, `UNIQUE(group_name, path_prefix)`; maps an IdP group to a path prefix its members may read.

  Both are created by `ensureAuthTables` at startup as ordinary logged tables — losing them in a crash would log everyone out and drop every grant, so never make them `UNLOGGED`.
- **`scan_sessions`** — one row per `fs_indexer` or `fs_aggregator` run (`session_id`, `scan_type`, `status`, `files_scanned`, `started_at`, `ended_at`); queried by `/api/scans`. `status` is `'running'`, `'success'`, or `'failed'`, written by the Rust process itself (via `fs_common`'s scan-session helpers) — `fs_api` only reads it. `files_scanned` is likewise written directly by the scanning process rather than derived, so this table is not fully normalized against `filesystem_index` by design.

All queries use parameterized statements (`$1`, `$2`, …) except `listIdentityStats`, which uses `fmt.Sprintf` for `ORDER BY` with an allowlist-validated column and direction.

`SearchFiles` translates a PostgreSQL regex parse failure (SQLSTATE `2201B`, or `54000` for an over-complex pattern) into **400** rather than 500, but only when the request actually used a `regex`/`regex_i` operator, so unrelated query failures still read as server errors. The validation is deliberately left to PostgreSQL: those operators compile as POSIX ARE, which differs from Go's RE2, so pre-checking with `regexp.Compile` would reject valid patterns and accept invalid ones.

### Authentication

Two modes, selected by whether `auth.oidc.issuer` is set in config:

**Local mode** — single username/password stored in config. Compared with `crypto/subtle.ConstantTimeCompare` to prevent timing attacks.

**OIDC mode** — standard OAuth2 Authorization Code flow:
1. `GET /auth/oidc/start` → generates a random state, sets `oidc_state` cookie, redirects to provider
2. Provider redirects to `GET /auth/callback` → validates state, exchanges code, verifies ID token, extracts email/sub as username
3. Session issued

**Sessions** — server-side and revocable. The `HttpOnly`, `SameSite=Lax` `session` cookie holds 32 random bytes (hex); the `sessions` row stores only their SHA-256, so reading the table yields no usable cookie. Lifetime 24h. Logout deletes the row, which bites on the very next request. Deploying this design logged everyone out once (old JWT cookies match no row). `auth.session_secret` no longer signs anything but is still validated at startup so existing configs keep working.

**OIDC re-check** — `loadSession` → `recheckSession` asks the IdP about the user at most once per `auth.oidc.recheck_interval` (default 5m) by spending the refresh token. The re-check is claimed atomically (`UPDATE … WHERE checked_at < now() - interval RETURNING refresh_token`) so concurrent requests don't spend a rotating token twice. **Any failure revokes** — refresh error, IdP unreachable, missing claims, changed identity, or failing the allowlists — since an unanswered re-check is indistinguishable from a disabled user. Otherwise the groups are re-read and stored. If the IdP issued no refresh token, the session is capped at one recheck interval (add `offline_access` to `extra_scopes`). IdP group changes therefore take effect within `recheck_interval`; logout and grant edits take effect immediately. Revoking a user is done at the IdP (disable them, end their sessions, or drop them from a group); there is no revoke button in Cuttlefish. Back-channel logout is not implemented.

**Roles** — `resolveAccess` runs on every request in `authMiddleware` and puts an `access` (`user`, `role`, `prefixes`) in the context:
- `admin` — any group in `auth.oidc.admin_groups` (required in OIDC mode); in local mode the single local user is always admin. Everything, plus `/api/admin/*`.
- `viewer` — any group in `auth.oidc.viewer_groups`. Reads everything.
- `restricted` — everyone else: only paths under the prefixes `access_grants` gives their groups, loaded fresh per request. A grant for group `*` applies to every user, and `{user}` in a grant's path expands to `grantUser(identity)` — the identity (`username_claim`, else email, else sub) with `@domain` stripped and lowercased — so `*` → `/home/{user}` gives `joshua@corp.com` `/home/joshua`. An identity whose stripped name is empty, `.`/`..`, or contains `/` or NUL is skipped for that grant rather than expanded, since it would climb out of the template. Stripping the domain means `joshua@a.com` and `joshua@b.com` get the same home; restrict with `allowed_domains` when more than one domain can sign in.

Groups come from `auth.oidc.groups_claim` (default `groups`; an array, or a single string). Google sends no groups claim, so Google users are all `restricted`.

**Enforcement** — `access.allows(p)` refuses non-canonical paths (`path.Clean(p) != p`, or not absolute) and then requires `p == prefix` or `p` under `prefix + "/"`; a `/` prefix allows all. `/api/list`, `/api/file/stats` and `/api/dir/stats` return 403 outside the prefixes — ancestors included. `/api/user/list` and `/api/group/list` summarise the whole index, so `fullAccessMiddleware` returns 403 to restricted users. `/api/search` is AND-scoped by `scopeClause` (`f.path = prefix OR f.path LIKE escaped_prefix || '/%'`). `adminMiddleware` gates `/api/admin/*`. Unit tests for these pure functions are in `access_test.go`.

### Route map

```
GET  /auth/mode           — returns "local" or "oidc" (unauthenticated)
GET  /auth/me             — {user, role, prefixes} for the session (behind authMiddleware; 401 without one)
POST /auth/login          — local login (JSON body: username, password)
POST /auth/logout         — deletes the session row and clears the cookie
GET  /auth/oidc/start     — begins OIDC flow (oidc mode only)
GET  /auth/callback       — OIDC callback (oidc mode only)

GET  /api/list            — list directory children (?path=, &include_stats=true)
GET  /api/file/stats      — single non-directory entry's metadata (?path=)
GET  /api/dir/stats       — single directory metadata (?path=, &include_stats=true)
                            (list/file/dir: 403 for a restricted user outside their prefixes)
GET  /api/user/list       — user storage stats (?sort_by=, &order=, &limit=, &offset=); 403 for restricted
GET  /api/group/list      — group storage stats (same params); 403 for restricted
POST /api/search          — search; restricted users only see results under their prefixes
GET  /api/scans           — scan_sessions history, newest first (?limit=, &offset=); scan_type, status and files_scanned are read straight off the row

GET    /api/admin/grants   — list access grants (admin only, as are all /api/admin/*)
POST   /api/admin/grants   — create {group_name, path_prefix}; prefix stored path.Clean'd; 409 on duplicate
DELETE /api/admin/grants   — delete ?id=

GET  /swagger/            — Swagger UI (requires session)
/                         — serves compiled UI from ui/build/; falls back to index.html for SPA routing
```

### Config (`fs_config.yml`)

```yaml
database:
  host: localhost
  user: postgres
  password: "..."
  dbname: fs_index
  sslmode: verify-full   # require encrypts but does not authenticate the server; never use "disable" in production

auth:
  session_secret: "..."  # must be ≥32 chars and not the example default; validated, but no longer signs anything

  local:                 # used when auth.oidc.issuer is absent
    username: "..."
    password: "..."

  oidc:                  # when set, local auth is ignored
    issuer: "https://accounts.google.com"
    client_id: "..."
    client_secret: "..."
    redirect_url: "http://host/auth/callback"
    # allowed_users: ["..."]           # optional: only these identities get a session
    # allowed_domains: ["example.com"] # …or only these email domains; both unset = allow any verified identity
    groups_claim: groups               # default "groups"; array or single string
    username_claim: upn                # optional identity claim; default email, then sub
    extra_scopes: ["groups", "offline_access"]  # offline_access → refresh token → sessions survive re-checks
    admin_groups: ["cuttlefish-admins"]          # required in OIDC mode (fatal if empty)
    viewer_groups: ["cuttlefish-auditors"]       # read everything
    recheck_interval: 5m               # Go duration; default 5m
```

`config.go` fatally rejects an empty, default-example, or short-than-32-char `session_secret` at startup, and in OIDC mode an empty `admin_groups`.

## Build

Use the root Makefile from the repo root:

```bash
make build-api        # build the Go binary (fs_api/fs_api)
make swagger-api      # regenerate Swagger docs then build
make run-api          # swagger + build-ui + build-api + run
make all              # build everything (indexer, aggregator, ui, api)
```

For a debug build (enables `debugLog` per-request logging):

```bash
make build-api-debug
# or directly:
cd fs_api && go build -ldflags "-X main.debugMode=1" -o fs_api .
```

`debugMode` is a linker-set string in `middleware.go`, empty in a normal build. It is deliberately **not** a `//go:build debug` file pair: mutually exclusive tagged files always leave one of the two outside the active build configuration, and gopls reports "No packages found" on whichever one the editor isn't type-checking.
